# 红动漫社萌战 · 设计说明书

面向协同开发者的技术设计文档。面向使用者的操作说明见 [用户手册](./用户手册.md)。

**主工程目录：`demo/`**（Next.js）。仓库内 `萌战/` 为历史归档，勿作为 npm 根目录。

---

## 1. 目标与范围

校园二次元「萌战」投票活动站：管理员配置对阵与角色，用户在开放时段内投票；支持决斗（1v1）与小组赛（n 选 m）；提供战报与防刷票（微信绑定 / 开发模拟 openid）。

| 已纳入 | 暂未纳入（见 §8） |
|--------|-------------------|
| Session 登录、全局票配额 | 生产级微信 OAuth 联调闭环 |
| 决斗 / 小组赛对阵组 | 晋级淘汰树自动生成 |
| 时段门禁 + 阶段分栏 | 多票种（普通票/资深票） |
| 战报、角色图集评论 | 问卷星等外部 Webhook |
| Admin CRUD | Postgres / 多实例部署 |

```

  → 读会话 getCurrentUser()
  → 挂载 Client 组件
```

## 3. 领域模型

### 3.1 ER 概要

```
Tournament 1──* Round 1──* Matchup
                              │
                              ├──* MatchupParticipant *── Character
                              ├──* VoteStat            *── Character
                              └──* VoteRecord *── User

User 1──1 VoteQuota
User 1──* Session
Character 1──* Comment *── User
```

### 3.2 核心表说明

| 模型 | 文件 | 职责 |
|------|------|------|
| `Matchup` | `schema.prisma` | **对阵组**：`mode`=`duel`\|`group`，`voteLimit`=每人可选角色数 m，`startAt`/`endAt`/`status` |
| `MatchupParticipant` | 同上 | 组内角色与 `sortOrder` |
| `VoteStat` | 同上 | `(matchupId, characterId)` 公开累计票 |
| `VoteRecord` | 同上 | 用户投票明细；唯一键 `(userId, matchupId, characterId)` |
| `VoteQuota` | 同上 | 用户全局 `totalLimit` / `usedCount` |
| `Session` | 同上 | Cookie `moe_session` 对应 token |

决斗赛：恰好 2 个 participant，`voteLimit=1`。  
小组赛：≥3 个 participant，`1 ≤ voteLimit ≤ n`。

阶段 **不入库**，由 `lib/match-phase.ts` 的 `resolveMatchPhase()` 根据 `status` + 时间计算：`live` | `upcoming` | `ended`。

### 3.3 投票规则（服务端强制）

实现：`lib/services.ts` → `submitVote()`。

1. 用户须微信绑定（或开发模拟 openid）；`assertWechatBound`
2. 对阵须 `phase === live`；`assertMatchupOpenForVote`
3. 角色须在 `MatchupParticipant` 内
4. 同一用户对同一角色不可重复投（唯一约束）
5. 该用户在该对阵组已投角色数 `< voteLimit`
6. 全局 `usedCount + votes ≤ totalLimit`
7. 事务内：写 `VoteRecord` → 增 `VoteStat` → 增 `VoteQuota.usedCount`

决斗与小组赛共用此路径；决斗额外保证 `voteLimit=1` 且组内只能投一次。

## 4. 设计逻辑与复杂功能

### 4.1 对阵阶段与三分栏

| 文件 | 作用 |
|------|------|
| `lib/match-phase.ts` | `resolveMatchPhase` / `assertMatchupOpenForVote` / 时间格式化 |
| `GET /api/bracket/active` | `phase` + `group` 过滤；附带 `counts` |
| `components/BracketView.tsx` | 进行中 / 未开始 / 已结束 Tab |

`status=ended` 或 `now >= endAt` → ended；`now < startAt` → upcoming；否则 live。

### 4.2 双赛制 UI 分支

`BracketView` 按 `matchup.mode` 渲染：

| mode | 组件 | 交互 |
|------|------|------|
| `duel` | `DuelCard` | 左右 VS、票比条、两侧投票按钮 |
| `group` | `GroupStageCard` | 网格卡：立绘、票数、「投票 / 已投票」 |

用户态字段由 `getMatchups({ userId })` 注入：`userVoted`、`userVoteCount`、`userRemainingInGroup`。

战报 `ReportView` 同样按 mode 分支（决斗 VS / 小组排名网格）。

### 4.3 管理端创建对阵组

| 文件 | 作用 |
|------|------|
| `components/AdminPanel.tsx` → `MatchupAdmin` | 表单：模式、角色、m、时段 |
| `lib/admin-services.ts` → `createMatchup` | 校验 n/m，写 Matchup + Participants + VoteStats |
| `POST /api/admin/matchups` | 入参 `mode` / `characterIds` / `voteLimit` / … |

### 4.4 鉴权双轨

| 身份 | 机制 | 关键文件 |
|------|------|----------|
| 普通用户 | Cookie Session + `wechatOpenid` | `lib/auth.ts`，`SESSION_COOKIE` |
| 管理员 | 独立 Admin Cookie（用户名密码） | `lib/admin.ts`，`ADMIN_*` |

管理员登录会建立 `openid = admin:system` 的用户；导航「管理」仅 `isAdminUser(user)` 为真时显示（`SiteNav.tsx`）。  
开发登录：`loginWithDevMock` → openid `dev:<hash(nickname)>`，禁止昵称 `admin`。

### 4.5 微信 OAuth（已实现代码路径）

| 步骤 | 位置 |
|------|------|
| 发起授权 | `GET /api/auth/wechat` → `lib/wechat.ts` |
| 回调换 code | `GET /api/auth/wechat/callback` |
| 建用户/会话 | `loginWithWechat()` |
| 配置自检 | `GET /api/auth/config`，`lib/wechat-setup.ts` |

本地 `localhost` 无法配置为微信授权域名；需公网 HTTPS 才可真机联调。当前 Demo 依赖 `ALLOW_DEV_LOGIN`。

### 4.6 角色图集

图集存 `Character.galleryJson`（JSON 数组），类型 `lib/gallery.ts`。  
上传落盘 `public/uploads/characters/`，管理 API 支持 multipart（立绘 / 图集）。立绘展示：`CharacterPortrait.tsx`（有图用图，无图用色块+emoji）。

### 4.7 评论敏感词

`lib/word-filter.ts` + `data/banned-words.txt`；`createComment` 前 `assertCleanComment`。

## 6. HTTP API 一览

除特别说明外，用户接口需携带 Session Cookie；管理接口需管理员已登录。

### 6.1 认证

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/auth/me` | 当前用户 |
| GET | `/api/auth/config` | 微信/开发登录是否就绪 |
| POST | `/api/auth/login` | 开发昵称登录 body:`{nickname}` |
| DELETE | `/api/auth/login` | 退出登录（清 Session Cookie） |
| GET | `/api/auth/wechat` | 跳转微信授权 |
| GET | `/api/auth/wechat/callback` | OAuth 回调 |

### 6.2 对阵与投票

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/bracket/active?group=&phase=` | 对阵列表；含 `counts`、用户投票态 |
| GET | `/api/bracket/report` | 战报 summary / leaderboard / matchups |
| POST | `/api/vote/intent` | `{matchupId, characterId, votes?}` |
| GET | `/api/vote/my-records` | 当前用户投票记录 |

`getMatchups` 返回要点：`mode`, `voteLimit`, `characters[]`, `characterA/B`（决斗兼容）, `phase`, `canVote`, `winners`, `userRemainingInGroup`。

### 6.3 角色与评论

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/characters` | 角色列表（含总票） |
| GET | `/api/characters/[slug]` | 详情 |
| GET | `/api/characters/[slug]/stats` | 各对阵得票 |
| GET/POST | `/api/comments` | 列表 / 发表（需登录） |

### 6.4 管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET/POST/DELETE | `/api/admin/auth` | 管理员登录态 |
| GET/POST/PATCH/DELETE | `/api/admin/characters` | 角色 CRUD、立绘/图集 multipart |
| GET/POST/PATCH | `/api/admin/matchups` | 对阵组；PATCH 含 `status` 或 `action:schedule` |
| GET/DELETE | `/api/admin/comments` | 评论审核删除 |

**创建对阵 POST body 示例：**

```json
{
  "mode": "group",
  "characterIds": [1, 2, 3, 4],
  "groupLabel": "G",
  "voteLimit": 2,
  "roundName": "32强 · 小组赛",
  "startAt": "2026-07-28T12:00",
  "endAt": "2026-08-04T12:00"
}
```

决斗：`mode:"duel"` 且恰好两个 id（或兼容 `characterAId`/`characterBId`）。

## 9. 本地开发约定

1. **只在 `demo/` 下** `npm install` / `npm run dev`
2. Schema 变更：改 `prisma/schema.prisma` → `npx prisma db push`（开发库）→ 必要时 `npm run db:reset`
3. `db:reset` 会清空业务数据并重新 seed；勿对生产库使用
4. 上传图片在 `public/uploads/characters/`，重置脚本会清理上传文件
5. UI 主题：深色粉红活动页；新增页面尽量复用 `glass-panel`、`group-tab`、`phase-tab` 等现有 class

### 9.1 推荐阅读顺序（新人）

1. `prisma/schema.prisma`
2. `lib/match-phase.ts` → `lib/services.ts`（`getMatchups` / `submitVote`）
3. `components/BracketView.tsx`
4. `lib/admin-services.ts` → `AdminPanel.tsx` 对阵 Tab
5. `lib/auth.ts` + `lib/admin.ts`
